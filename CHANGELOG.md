# Changelog

## Unreleased

- SWE and terminal (tmax) served as verifiers entries through the bridge; their per-env adapters were removed from reliquary-environments. The conformance report records fresh-box re-gradings and in-place helper retries (`regraded`, `helper_retries`, per run and in total) even when the case passes.
- Bridge v2: `Task.setup`, `Task.finalize` and the new optional `Task.grading_setup` (the pristine grading box, before the restore) run in the scoring process like the rewards; bridged identities become `.vfb2`. A setup that fails fails the open; a finalize that raises grades 0 `extract_failed`, one past its step deadline `extract_timeout`; a failed `grading_setup` is ours (`aborted`). A declared setup timeout below 35 s is refused (a scoring process needs 30 s left to start). `grading_setup` is killed 35 s before the step deadline (the restore and the scoring still start), so a task with it needs a grading step of at least 70 s. Finalize's commands are followed by a stop of every process of the box, like the reward's. Scoring processes run with `PYTHONHASHSEED=0`. A RecursionError in a runtime call is the env's code's, not a protocol failure.
- Added signed episodes for agentic environments, off by default (`EPISODES_ENABLED`). A validator-signed session token opens an episode. Calls run strictly in order and can be retried by `(turn, k)`. Every output is signed with the machine's Ed25519 key and hash-chained to the previous record. Finishing grades the final state in a pristine box from the same image and signs the reward. An episode always ends with a signed final record whose status says whose doing it was: `graded`, `expired` and `budget_exhausted` (the agent's), `box_failed` (the agent's box became unusable through its own actions; not paid, not voided) or `aborted` (our side failed; void).
- Added `reliquary_sandbox.attest`, which depends only on the standard library and `cryptography`. It provides canonical JSON, session tokens, record types, signing, `verify_transcript`, a pure offline verifier, and the check for signed capacity reports.
- Added `reliquary_sandbox.episode_task`, the declaration environment packages implement (`sandbox_task(split, index)`) with its failure contract, and a local runtime that runs their existing grading code unchanged, including vetted state archives.
- Task boxes run as shipped under gVisor with network disabled, and every plumbing command runs from a pinned, read-only static busybox rather than from the image. Their writable root is capped by an xfs project quota. Episodes are refused on a host without that quota (unless a test flag is set), the pinned runsc, a Unix Docker socket, or a Docker pidfile and `/proc` the controller can read. A command that times out loses only its process group, output beyond the cap is cut and flagged, and CPU is accounted per call.
- Added the generic verifiers bridge: an `EPISODE_ENVS` entry `verifiers:<taskset-id>==<version>` serves a standard verifiers v1 Taskset with no per-env adapter. `SandboxRuntime` (a verifiers `Runtime` over the signed task runtime), `task_from_verifiers` (image through the env's lock file, limits from `TaskData`, `Task.setup` / `Task.finalize`, safe artifact archives) and grading in a pristine box through `Task.score`, run in a separate unprivileged scoring process without network (a seccomp filter refuses every socket but `AF_UNIX`; without it the process refuses to score). An exception from the env's own scoring code once the agent's state is restored is graded 0 `grading_failed` (logged and counted per env), never aborted: the agent's bytes can cause it. `SandboxTask.content_sha256` puts a task's content hash in its fingerprint.
- `compose.episodes.yaml`: the Compose override for episode hosts serving verifiers envs (scoring capabilities, `pids_limit`, `mem_limit`, `kernel.shm_rmid_forced`, a `0700` `/tmp` and the `/scoring` tmpfs). `compose.yaml` alone keeps the previous settings for tenant-API and corpus-executor hosts.
- Added the env conformance suite and `reliquary-sandbox-conformance`: reference solutions grade 1, declared and built-in attacks grade 0, runs are deterministic.
- Added a signed capacity report (`GET /capacity`), an optional heartbeat push, and `scripts/test-xfs-docker.sh` for running the live tests on an isolated xfs-quota daemon.
- A `verifiers:` entry of `EPISODE_ENVS` whose module is not installed (or does not import in the scoring wrapper) now refuses startup: the controller imports the module of every verifiers entry in the scoring wrapper at start (preload check) instead of grading its episodes `aborted` later. Only verifiers entries are scored there: a configuration of `module:callable` envs alone starts no scoring forkserver, and the scoring path never imports their modules.
- Security fix, grading change for every env (verifiers or not): `LocalRuntime.read` refuses to read through a link restored from the agent's state that leads outside the restored roots (`StateUnreadable`, an `OSError`: graded 0 `state_unreadable` when the env lets it through, and an env reading it as a missing file grades 0). A legacy env whose grader read the agent's file through such a link (for example a link to a reference answer under `/tests`) used to read its target.

## 0.1.0

- Added a self-hosted Linux container service for bounded miner workloads, agents, and evaluations, using approved Docker images with the gVisor runtime.
- Added tenant credentials, scoped guest gateway access, resource quotas, lifecycle reconciliation, lifetime limits, and command deadlines.
- Added synchronous and asynchronous Python SDKs with typed models, batch status polling, retry handling, Connect protobuf commands, and file transfer.
- Added bounded workspace file checkpoints and restore into new guests. Checkpoints retain filesystem contents only; process and VM state are outside this release.
- Added command-line lifecycle, command execution, file handling, checkpoint listing, restore, and checkpoint deletion workflows.
- Added pinned guest and controller builds, loopback Compose deployment, HTTPS proxy guidance, and a checksum-verified runtime installer.
- Added SDK, service, runtime, and CLI tests. Linux CI qualifies actual gVisor lifecycle, commands, file transfer, tenant separation, deadline cleanup, and workspace restore, then builds and starts the Compose controller.

Release qualification requires the unit checks, package build, Linux runtime integration suite, and Compose readiness check to pass for the revision being deployed. This release does not provide a hosted VM fleet, GPU allocation, SSH, public guest networking, image builds, or billing. Production deployment requires a configured Linux host, approved images, generated tenant credentials, and an HTTPS entry point for remote clients.
